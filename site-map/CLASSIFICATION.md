# Classification — criteria, heuristics, counts, limits

Part of the Ultimate Site Map for wbic16 (Will Bickford), generated 2026-10-31. See [SITE-MAP.md](SITE-MAP.md) and [sitemap.json](sitemap.json).

## Repo-level criteria (exactly one primary class per repo)

- **finished** — complete and usable as-is. Positive signals: deployed or live (sites, mirrorborn.us), ratified/stable text (SBOR V4), released library with packaging and tests, a tool in daily use (SQ as run by Emise). A historic-but-complete artifact (phext-notepad, framed by its own README as a reference implementation) also counts.
- **prototype** — working implementation, demonstrable end-to-end or in large part, but unstable, in-progress, or superseded-in-progress: active Rust systems (vtpu, phext-lattice), web apps, the human repo's growing phext corpus, most 2025–2026 code.
- **idea** — the repo's substance is a design, plan, spec, manifesto, or paper, with little or no implementation: README-only projects, written plans (MercurialDyson), theory papers (Cosmic-Cognitive), concept essays (phext, the 2023 origin repo). exodroid is represented as a plan only, at Will's direction, even though its repo also carries committed build artifacts; its files are not cataloged.
- **fragment** — partial or residual: stubs (phextos), empty placeholders (sq-cloud, mytheon-arena, exo-motes, sq-howto — all zero files), single-file scraps, debris collections (compost is deliberately this), and upstream forks with no Will-authored project state.

## Basis labels

- **basis = read (45 repos)** — a classifier actually read the repo's README (raw, default branch) and usually its contents listing, and the class rests on that evidence.
- **basis = heuristic (60 repos)** — classified from API metadata only: description, size, file count, language, last update, fork flag. Heuristic rules: 0 files or near-0 KB with no description → fragment; description announcing a plan/spec with tiny size → idea; a named tool/app with substantial size and recent activity → prototype; a live site repo → finished. Heuristic verdicts are the ones most likely to be wrong in detail; the class criteria above are the court of appeal. Clones (53) carry no basis label at all: their records are name-only, and no classification evidence is kept for them beyond the prune decision itself. The plan-only exodroid, the summary-level evals and compost, the footnote exo-archives, and the ten dropped repos likewise carry no basis: their representations rest on Will's direction, not on classification evidence.

## File-level classification (machine heuristic, labeled as such)

Every individually listed file (5,018 files across the 105 repos cataloged in full — every cataloged repo's files are individually listed, after the build-artifact delisting below) carries a class in sitemap.json, assigned by these rules, in order:

1. Zero-byte file → **fragment**.
2. A Markdown/text file whose path names a plan, design, spec, manifesto, proposal, or roadmap → **idea**.
3. Otherwise the file **inherits its repo's class** (a working source file in a prototype repo is prototype work; a finished site's pages are finished).

**Build-artifact delisting rule (Will's direction, 2026-10-31).** A file is a build artifact, and is removed from every file list and every count in this map, when any test matches: (a) any directory segment of its path is named `target`, `dist`, `build`, `out`, `node_modules` or `__pycache__`; (b) its extension is a compiled artifact: `o`, `a`, `rlib`, `rmeta`, `so`, `dll`, `dylib`, `exe`, `class`, `pyc` or `pyo`; or (c) it has no file extension and is larger than 1 MB — an extensionless compiled binary (conventional extensionless text files such as LICENSE, Makefile, Dockerfile, README, CHANGELOG, AUTHORS or COPYING are small in practice and are not caught by this clause; an extensionless file over 1 MB that is plausibly data or text would be held as a documented exception rather than delisted — none arose). `.wasm` is explicitly **not** an artifact under this rule — a wasm file can be source intent — and wasm files are kept. Applied estate-wide, the rule delisted 435 files and 44,330,273 bytes: 432 files under build directories (324 of them in exo-plan alone, 323 of those under a `target/` tree, and 65 more in phext-dot-io-v2's `dist/`) and only 3 compiled-extension files elsewhere (phext-notepad's `trs.dll` and `trs.exe`, libphext-cpp's `terse-string.exe`) — the rlib/rmeta bulk had already left the catalog with exodroid's plan-only reduction. When a delisted file was individually classed, its class count left with it. Clause (c) was added in the second delist round the same day (see DELIST2-REPORT.md): it matched exactly two files estate-wide. One was delisted outright — hello-phext-deploy's extensionless `hello-phext` ARM binary (8,656,360 bytes) — bringing the rule's totals to 436 files and 52,986,633 bytes. The other match, a UUID-named media blob in compost's chrys/media dump (4,469,118 bytes), left the catalog in the same round when compost was reduced to summary level and is accounted there, not here. Two extensionless files sit just under the 1 MB line and are untouched by the clause: compost's second UUID media blob (981,364 bytes, also leaving with compost's reduction) and exollama's `test` (821,472 bytes, still cataloged).

Resulting file-class totals: {"fragment": 359, "prototype": 2375, "idea": 1230, "finished": 1054}. (Before the prune, clones contributed a further 13,847 listed files, almost all fragment; they are no longer cataloged. The first drop directives removed a further 1,928 listed files, all of exodroid's: 1,895 idea and 33 fragment; notepad-plus-plus had no individually listed files — it had been recorded as a count plus an extension histogram. The delist round then removed 5,237 more listed files: 2,113 in the five newly dropped repos, 1,728 in evals (now a summary-only record), 961 in the mental-space/ subtree of site-mirrorborn-us (now held at summary level: a scroll-per-file Markdown rendering of CYOA, 802 files, and incipit, 159 files, counted in a note on that repo's record and entry), and 435 delisted build artifacts. The second delist round then removed 229 more listed files: 175 in compost (now a summary-only record), 30 in the four newly dropped language learning repos (AdventOfCOBOL, aoc2024, hello-ada, hello-forth), 23 in exo-archives (now a footnote record), and 1 extensionless binary in hello-phext-deploy delisted under clause (c) of the build-artifact rule.) These are machine labels for navigation, not per-file human judgments; the ~40 most significant original repos are the ones whose READMEs were human-read at repo level, and their file lists are complete in sitemap.json (largest: exo-plan 1,029 files, mirrorborn 388, vtpu 379, eigenhector_mandala_translator 317, exollama 310).

## Known limits

- **nixpkgs tree truncation:** GitHub's recursive tree API capped the response during the original enumeration; nixpkgs was recorded at 41,458 files and its true count is higher. It was the only truncated tree. nixpkgs is now a name-only clone, so the figure survives here only as the record of that limit.
- **Dropped by direction:** ten repos were dropped from this map at Will's direction (2026-10-31), named here only: notepad-plus-plus (its phext integration is unfinished; finishing it is a tracked follow-up) and phcc (his phexted TinyCC work is unfinished; finishing it is tracked separately) — the two forks-with-his-work dropped over unfinished phext work; shoggoth and openfang, forks dropped outright; ziglings and rustlings-homework, dropped as language learning exercise sets; and four more language learning exercise sets dropped in the second delist round the same day: AdventOfCOBOL, aoc2024, hello-ada and hello-forth.
- **Summary level by direction:** evals (1,728 files: registry, elsuite, solvers, completion_fns, cli, utils), compost (175 files: chrys 119, including the chrys/media single-day dump of UUID-named generated media from 2026-02-21, phex 34, lux 21, plus a root readme) and the mental-space/ subtree of site-mirrorborn-us (961 files: a scroll-per-file Markdown mirror of CYOA, 802 files, and incipit, 159 files) are held at summary level — their contents are summarized in place and counted in the notes there, but their files are not individually listed. Build artifacts are likewise delisted estate-wide under the rule in the file-level section (436 files, 52,986,633 bytes, including the one clause (c) extensionless-binary delisting).
- **Footnote by direction:** exo-archives is represented by a footnote only (in SITE-MAP.md's Scope and limits, and as a `footnote` record in sitemap.json): an archive vault holding Will's tweet archive (wbic16/tweets.json, 54,819,221 bytes, about 55 MB) and 22 small files — 23 files / 54,963,781 bytes in all — none individually cataloged. It is footnoted, not dropped: it stays inside the represented count (162) but carries no class, cluster or basis.
- **API size vs content size:** the API `size` field (used by some heuristics) counts repository storage including history and can diverge wildly from tree content (exodroid: 160 MB API vs 650 MB of blobs — exodroid is now represented as a plan only and its files are no longer cataloged, see DROPS-REPORT.md; openpilot: 2.4 GB API vs 9.3 MB on its default branch tree, because most of it lives in history/LFS pointers; openpilot has since been pruned to a name-only clone). Tree numbers in this map are the default-branch truth.
- **Default branch only.** Other branches (notably `exo` where it is not the default) are not enumerated; in several repos (SQ, vtpu) the exo branch carries a newer README than main.
- **A snapshot, not a monitor.** Taken 2026-10-31; the core repos move daily.
- **Private repos are out of scope** (no access) and do not appear.
- Classification of borderline repos (historic-but-complete vs prototype, e.g. phext-notepad; living corpus vs finished, e.g. human) involves judgment; the basis labels say where that judgment was exercised on evidence vs metadata.
